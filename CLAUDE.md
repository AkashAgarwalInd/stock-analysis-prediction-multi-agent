# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Multi-agent stock analysis and probabilistic next-5-trading-day forecaster for Indian NSE stocks (LangGraph + Gemini + SQLite + Monte Carlo quant baseline). Educational/research only — output must never be framed as buy/sell/hold advice.

`Plan.md` is the authoritative spec (≈4300 lines). Its phase list (section "Phase 1 — Foundation" … "Phase 18 — Hardening", near the end of the file) is the build order: complete a phase with passing tests before starting the next, and ask before deviating from the specified architecture. Note the README uses an older, different phase numbering — trust `Plan.md`.

## Commands

```bash
uv sync --dev                       # install (or: pip install -e ".[dev]")
pytest                              # all tests (config in pyproject: -v --tb=short, asyncio_mode=auto)
pytest tests/phase5/                # one phase's tests
pytest tests/test_quant_forecast.py::TestClassName::test_name   # single test
ruff check src tests && ruff format src tests
mypy src                            # strict mode
python demo.py                      # end-to-end demo of data + quant layers (hits real yfinance/RSS)
alembic upgrade head                # DB migrations (alembic/versions/)
python -m stock_analysis.cli.main --help   # Typer CLI (also installed as `stock-analysis` and `stock-agents`): init, migrate, analyze, review, backtest, scorecard, evaluate, calibration, status, config
```

The README lists CLI commands like `resolve`, `price`, `forecast` — these are not implemented in `cli/main.py` (`analyze` is the live forecast).

`ruff check src tests` passes, but only because ~250 style findings in `src/` are deferred via `ignore`/`per-file-ignores` (see the comments in `pyproject.toml`) — "clean" here does not mean the codebase satisfies the selected rule set. `ruff format` would reformat 23 files, so it is not part of the gate yet either. `mypy src` runs to completion but still reports ~110 strict-mode errors (mostly bare `dict`/`list` type args); don't treat it as a gate yet.

`tests/conftest.py` sets `APP_ENV=testing` and a dummy `GEMINI_API_KEY`, and clears the `get_settings()` lru_cache around every test. `tests/test_gemini_smoke.py` is skipped wholesale (google.generativeai / pkg_resources issue). Older phase tests live flat in `tests/`; Phase 5+ tests live in `tests/phaseN/` (`tests/phase7` holds both the memory tests and the snapshot tests the user called "Phase 7"; `tests/phase9` is the outcome scorer; `tests/phase10` the backtest; `tests/phase11` postmortems, lessons and the learning cycle; `tests/phase12` calibration and shadow forecasts; `tests/phase13` scorecards; `tests/phase14` probability calibration and the track record; `tests/phase15` the review graph; `tests/phase16` learning wired into the forecast graph; `tests/phase17` the `analyze` command). Forecast fixtures (`migrated_db`, `store`, `memory_store`, `outcome_store`, `snapshot`, `adjusted_state`, ...) live in `tests/conftest.py`, with helpers in `tests/forecast_helpers.py` (fake LLMs) `tests/outcome_helpers.py` (synthetic actual prices) and `tests/learning_helpers.py` (forecasts re-dated to non-overlapping weeks on a weekday-only calendar, synthetic scoring, `FakePostmortemLLM`) and `tests/backtest_helpers.py` (synthetic stock/Nifty/VIX history on NSE trading days, with optional weekly swings or a post-cutoff "poison"); import them as `tests.forecast_helpers`.

## Architecture

Everything is under `src/stock_analysis/`. Data flows in layers:

1. **Data collection (deterministic, cached)** — `market/` (SymbolResolver, MarketPriceCollector, TradingCalendar, PriceCache) and `data/` (Fundamentals/News/MarketContext collectors behind a unified async `DataCollector`). All caches are SQLite-backed with per-type TTLs; collectors degrade gracefully when a source fails rather than raising.
2. **Indicators & quant** — `indicators/technical.py` (`compute_all_indicators`) and `quant/forecast.py` (`QuantForecaster` → `QuantBaseline` with P10/P50/P90, prob_up/flat/down, weekly vol). Volatility is pluggable via the `VolatilityModel` ABC (default `EWMAVolatility`, λ=0.94); simulations take a seed for reproducibility.
3. **LLM layer** — `llm/factory.py` `LLMFactory` / `get_llm_factory()`; call `generate_structured(role=..., prompt=..., response_schema=<PydanticModel>)`. The JSON schema is appended to the prompt (not passed as Gemini's `response_schema`, which rejects free-form dict fields); API errors retry once on the FALLBACK model, while schema violations raise `ValidationError`. Temperature/max tokens default to settings. Model IDs come from settings (`GEMINI_MODEL_PRIMARY/CRITIC/FALLBACK`), never hardcoded.
4. **LangGraph workflow** — `langgraph/workflow.py` `build_workflow()` / `compile_graph(llm_factory=None)`. State is the Pydantic `GraphState` (`schemas/graph_state.py`, `extra="forbid"` — any new node output key needs a field there). Topology:
   `review_matured` → `memory_loader` → `mark_collectors` → 4 parallel analysts (technical, fundamental, sentiment, context) → `guardrails` → `decision_engine` → `quant_baseline` (calibrated when a `LearningStore` is passed; the uncalibrated shadow is always kept) → `adjustment_gate` → `predictor` → `critic` → `revision` → (back to `predictor` while the critic fails, else) `final_forecast` → `join` → `forecast_snapshot` → `memory_writer` → END.
   Collector data is pre-loaded into state as compact summaries before the graph runs. All nodes are module-level functions (or `make_*` factories when an LLM is injected) so they can be unit tested directly. The Phase 6 loop is bounded by `MAX_REVISIONS` / `PREDICTOR_MAX_PROB_SHIFT` (settings, defaults 2 / 0.15); after the budget is spent the quant baseline ships with `fallback_to_quant=True`. The critic is deterministic and judges the *raw* predictor dict, because the strict `PredictorResult` schema rejects bad output before a critic could see it. Phase 6 schemas (`PredictorResult`, `CriticResult`, `FinalForecast`) are in `schemas/forecast_pipeline.py`.
   **Phase 7 snapshots** (Plan.md calls this Phase 8): `forecast_snapshot` builds an immutable `ForecastSnapshot` (`schemas/snapshot.py`, via `snapshots/builder.py`) and renders the report (`snapshots/report.py`). It is persisted only when a `ForecastSnapshotStore` (`database/forecast_store.py`) is passed to `compile_graph`; production code should call `langgraph/runner.py` `run_forecast`, which always persists and fails if a completed forecast or its price history was not stored. With a store, the quant node also saves the exact close series (`price_history_snapshots`), so `snapshots/reproduce.py` `reproduce_quant_baseline` can re-run a stored baseline bit-for-bit.
   **Plan.md Phase 7 memory**: `database/memory_store.py` `MemoryStore` (same SQLite DB, migration `003`; not LangGraph Store) holds per-forecast `ForecastInsight`s, lessons with an append-only evidence log (status candidate/active/retired is derived; `LESSON_ACTIVATION_MIN_EVIDENCE`=3, 2 for earnings-type categories), and the `TrackRecord` (`outcome_metrics` stays `None` until outcomes are scored). `memory_loader` puts a `MemoryContext` in state; `build_predictor_prompt` adds a PRIOR CONTEXT section only when it has content; the context is recorded in the snapshot's `data_inputs["memory"]` and shown in the report. Memory failures never block a forecast. All memory reads take an `as_of`/`before` cutoff for point-in-time use.
   **Plan.md Phase 9 outcome scoring** (`review/`, migration `004`): `OutcomeReviewer.review_matured(now)` finds matured original forecasts without an outcome, fetches actual prices for exactly the `[as_of, target]` window (`review/prices.py`, yfinance with dividend/split columns) plus Nifty 50, and calls the pure `score_forecast` (`review/outcome_scorer.py`, metrics in `review/metrics.py`). Matured = target session closed + `OUTCOME_DATA_DELAY_MINUTES`. Actual return comes from one consistent fetched series and is applied to the snapshot's `last_close`, so later dividend/split re-adjustment of history cancels out; unexplained daily moves beyond `OUTCOME_MAX_DAILY_MOVE_PCT` are invalid. The headline loss is the up/flat/down Brier score (`llm_value_added = baseline_loss - final_loss`); quantile (pinball) value added is stored too. Scored/invalid outcomes are stored append-only in `forecast_outcomes`/`outcome_daily`; unresolved ones are not stored and are retried. `stock-analysis review` runs the review graph (below) and prints the "Last forecast vs actual" section (`review/report.py`), postmortems, adaptation, scorecards and track record (`--no-llm` for rules-only postmortems).
   **Historical backtest** (Plan.md Phase 10; `backtest/`, `stock-analysis backtest --ticker RELIANCE --weeks 12 [--end D] [--no-llm] [--database P] [-o report.md]`). `run_backtest` builds back-to-back windows (each as-of is the previous target, so weeks never overlap) and runs them strictly in order on a simulated clock: forecast at the as-of close (`GraphState.run_at`, which memory, calibration and `made_at` use instead of the wall clock) → score at the target's data time → learning cycle → next week. Forecasts only see `HistoricalMarketData.as_of(d)` (`PointInTimeView`, passed to the graph as `price_fetcher`); evaluation uses `HistoricalPriceSource`, which raises `LookaheadError` beyond the session the clock has reached. Technical and market-context inputs are rebuilt point-in-time (`backtest/inputs.py`); fundamental and sentiment analysts are disabled (`GraphState.disabled_analysts`: placeholder report, no LLM call, excluded from guardrail coverage/consensus, the decision engine and the gate; recorded in the snapshot's `data_inputs`). `--no-llm` disables all four (quant only). Writes to a new `data/backtests/<TICKER>-<time>.db` by default (migrated in process via `database.migrations.upgrade_database`) and refuses a database holding any history timestamped at or after the first simulated forecast (`later_history`): records are written with past timestamps, so going back in time would change what point-in-time reads of later history return. A failing week is reported and the run continues; the report notes that LLM runs may carry pretraining knowledge of those dates (`--no-llm` does not).
   **Learning: postmortem, lessons, calibration** (Plan.md Phases 11-12, the user's "Phase 9"; `learning/`, migration `005`, `database/learning_store.py` `LearningStore`). `LearningCycle.run(now)` processes scored originals without a postmortem (oldest first): records one `decision_outcomes` row per decision (for later evaluation only — decision rules are never changed automatically), runs `run_postmortem`, applies lessons, and stores the postmortem last (the "processed" marker; earlier steps are idempotent). Then it retires stale lessons and re-estimates each ticker's calibration. A failing forecast is reported in `LearningReport.errors` and retried next run without blocking the others.
   - Postmortem (`learning/postmortem.py`, prompt `prompts/postmortem.txt`, versioned by content hash): facts are numbered `F<n>` (forecast-time, from the snapshot) and `H<n>` (hindsight: outcome, Nifty, corporate actions, news published between `made_at` and the target close — `learning/news.py` `RssHindsightNewsSource`, wired by `review --llm`; RSS only reaches ~14 days back). Expected noise (inside the 80% band, vol ratio 0.5–2) never calls the LLM and never yields a lesson. The LLM output (`PostmortemDiagnosis`, no metric fields) is checked in code: knowable claims citing H facts or quoting hindsight-only numbers move to hindsight, unknown fact IDs are dropped, an unsupported `primary_cause` (`cause_rejection`) or any LLM/schema error falls back to `classify_deterministically` with no lessons, and lessons must cite only F facts and not quote hindsight-only numbers (max 3).
   - Lessons (`learning/lessons.py`) are matched to open lessons by scope + category (not wording). A forecast counts once per lesson and never when its window overlaps one already counted. Ticker volatility lessons get deterministic confirm/contradict evidence from `vol_ratio`; lessons unconfirmed for `LESSON_STALE_AFTER_DAYS` are retired.
   - Calibration (`learning/calibration.py`, `CALIBRATOR_VERSION` in `versions.py`): `vol_multiplier = clip(1 + n/(n+k)·(median|z|/0.6745 − 1), 0.8, 1.5)` and a shrunk, bounded P50 bias shift only when persistent and significant, both measured against the *uncalibrated* baseline so versions never compound; nothing changes below `CALIBRATION_MIN_SAMPLES` (8) independent forecasts — forecasts whose windows overlap count once (newest kept, the rest listed in the evidence). A new `calibration_params` version (old/new values, reasons, evidence forecast IDs, n) is stored only on a material change. The quant node applies the latest version as of the run (unless `LEARNING_ENABLED=false`) using the same random draws, and always keeps the uncalibrated baseline: `ForecastSnapshot.calibration` / `uncalibrated_baseline` (`shadow_baseline` property) persist in `shadow_forecasts` and are covered by the snapshot hash when present. The scorer (`SCORER_VERSION` 2) scores the shadow too (`uncalibrated_loss`, `calibration_value_added`); `compare_benchmarks` compares uncalibrated quant, calibrated quant and final forecast.
   **Scorecards** (Plan.md Phase 13, the user's "Phase 11"; `learning/scorecards.py`, `schemas/scorecard.py`, `stock-analysis scorecard [--ticker] [--database]`, also in the backtest report). Computed on demand from immutable records with an `as_of` cutoff (`OutcomeStore.scored_forecasts`, `LearningStore.list_decision_outcomes`) instead of Plan.md's mutable scorecard tables: analyst directional hit rates (pooled, by ticker/sector/regime, 95% Wilson intervals; disabled/degraded analysts make no call), forecast quality by regime/ticker/sector (direction, MAE, mean signed error, Brier, 80% coverage), and per decision-engine decision the mean LLM value added with a 95% Student-t interval and how many forecasts were actually adjusted. Forecasts whose windows overlap a later one of the same ticker are left out (newest kept), as in calibration and lessons. No finding below `MIN_SAMPLES_DECISION_EVALUATION`; analyst weighting is only reported as eligible when `ANALYST_WEIGHTING_ENABLED` and `MIN_SAMPLES_ANALYST_WEIGHTS` (20) are met — no weighting is implemented; the forecast graph only shows a summary to the predictor (below).
   **Probability calibration and track record** (Plan.md Phase 14, §27-28/§31/§53-55; `learning/evaluation.py`, `schemas/track_record.py` — not `schemas/evaluation.py`, which holds unrelated legacy schemas). `evaluate_forecast(snapshot, outcome)` re-scores four variants on the same outcome with the scorer's metric definitions: naive flat (P50 = last close, direction flat, no probabilities/band), uncalibrated quant (`shadow_baseline`), calibrated quant and final forecast, plus sharpness ((P90−P10)/last close) and the PIT percentile (track record shows the share below P10 / below P50 / above P90). `reliability_table` buckets predicted probabilities (`PROBABILITY_CALIBRATION_BUCKETS`, default 10) against observed frequency (Wilson CI) with binary Brier, its Murphy decomposition and ECE; `probability_calibration` does P(up)/P(flat)/P(down) plus all classes pooled per probabilistic variant. `build_track_record` gives 8-week, 26-week and all-time windows by target date (IST) with LLM and calibration value added (Student-t CI) and how many forecasts were actually adjusted / calibrated (no LLM verdict when none was adjusted); no verdict below `MIN_SAMPLES_DECISION_EVALUATION` and no calibration finding below `MIN_SAMPLES_PROBABILITY_CALIBRATION`. `build_evaluation` loads independent scored originals as of a cutoff (same overlap rule as scorecards). Computed on demand, not stored in Plan.md's `probability_calibration` table. Shown by `stock-analysis evaluate [--ticker] [--database]` (track record + final-forecast calibration), `stock-analysis calibration [--ticker] [--database]` (calibration versions + all variants' probability calibration) and the backtest report (`BacktestResult.evaluation`). The forecast graph shows the final forecast's rolling window metrics to the predictor (below).
   **Review graph** (Plan.md Phase 15; `langgraph/review_graph.py`, not `review/` to avoid an import cycle with `learning/`). A separate LangGraph over the stores only — it never builds the forecast graph: `find_matured → score → postmortem → learning → calibration → scorecards → track_record`, on the Pydantic `ReviewState` (`run_at` is the clock, optional `ticker`). The steps are `OutcomeReviewer.find_matured`/`score` (returns outcomes plus per-forecast errors) and `LearningCycle.diagnose`/`apply`/`recalibrate` (`LearningCycle.run` still does all three); `apply` stores each postmortem last, so `ReviewState.postmortems` ends with only the stored ones. A step failing with a store/sqlite/`ValueError` error is appended to `ReviewState.errors` (as `"<step>: <msg>"`), left out of `completed_steps`, and the later steps still run. `run_review(now, ...)` defaults to the app DB; `stock-analysis review` and the backtest's weekly review (`compile_review_graph` + `invoke_review`) both use it. The calibration node always includes the requested ticker and also returns `benchmarks` per ticker for the adaptation section.
   **Learning wired into the forecast graph** (Plan.md Phase 16; `learning/context.py`, `tests/phase16`). The forecast graph starts with `review_matured`: with a `reviewer` (`compile_graph(..., reviewer=, outcome_store=)`; `review_graph.make_pre_run_reviewer`) it runs the review graph for the ticker at the run's clock and keeps a compact `PreRunReview` in `GraphState.review_summary` (also in the snapshot's `data_inputs["review"]`, only when a review ran); any failure is recorded there and never blocks the forecast. `run_forecast` always wires it (`review=False` skips it; postmortems use the forecast's LLM plus RSS hindsight news like `review --llm`, `review_llm=False` makes them rules only; `review_options` such as `price_source`/`calendar`/`news_source` go to the review graph). The backtest does not (it reviews each week itself) but passes `outcome_store`. `memory_loader` then calls `add_learning_context`, which adds to `MemoryContext` (point-in-time; `learning_loaded` lists the parts loaded, a part that fails — for any exception — is skipped with a `warnings` entry, and one whose store is not given stays `None`; the report shows the new sections only when something was loaded and says "not available" per missing part rather than "nothing yet"): `last_review` (`LastReview`: newest evaluated original via `OutcomeStore.latest_evaluated`, its postmortem cause if stored by then, lessons it created/confirmed via `MemoryStore.lessons_for_forecast`), `adaptation` (calibration in force, previous values, reasons, whether it changed since the previous forecast; version 0 = none yet), `scorecards` (`ScorecardSummary`: pooled analyst hit rates and per-regime quality) and `TrackRecord.outcome_metrics` (`OutcomeMetrics`: final-forecast metrics per track-record window; `distinct_windows()` merges nested windows holding the same forecasts). The predictor prompt shows all of it (current regime marked; the calibration is flagged as already applied) and the report adds "Last forecast vs actual", "System adaptation" and "Track record" sections after the header/before data quality. Report numbers may also be a snapshot value at 4 decimals (losses); avoid literal numbers such as "Nifty 50" or "80%" in report text — the integrity check rejects them.
   **`analyze` demo** (Plan.md Phase 17 / §76; `analysis/`, `stock-analysis analyze RELIANCE` or `"tata motors"` `[--database P] [--no-llm] [--no-review] [-o report.md]`; `stock-agents` is an alias). `run_analysis` resolves the query offline (`market.resolver.resolve_nse_ticker`, also used by the backtest), collects live inputs (`analysis/inputs.py`: `LiveInputSource` = yfinance prices + the cached `DataCollector`; `collect_inputs` reduces them to compact summaries — latest indicators via `indicators.technical.latest_indicator_summary`, non-empty fundamentals/market-context fields, news count + 10 newest headlines — and a failing source becomes `{"unavailable": reason}` instead of raising, listed under the report's data quality; bars after the last completed NSE session — today's while the market is open — are dropped) and calls `run_forecast` with `price_fetcher` returning the same bars, so the indicators and quant baseline share one series. Without `GEMINI_API_KEY` the LLM path still runs (analysts degrade, the quant baseline ships) and the CLI warns first. `--no-llm` disables all four analysts and passes `llm.DisabledLLM` (also used by the quant-only backtest); `--database` points at e.g. a backtest DB so the report shows its review, calibration and track record. The report (`REPORT_WRITER_VERSION` 6) carries the §76 parts: "Last forecast vs actual" is a quant baseline / final forecast / actual table (`LastReview.baseline_*`, from the snapshot's quant baseline and the outcome's `baseline_*` fields; old snapshots render "n/a"), "System adaptation" shows the calibration's effect on this forecast's P10–P90, and "Benchmark comparison" lists naive / uncalibrated / calibrated / final over the widest track-record window (`WindowMetrics.variants`).
5. **Guardrails** — `guardrails.py` `run_preflight_guardrails(state)` runs between analysts and the decision engine (missing reports, CRITICAL `DataGap`s, coverage, consensus confidence). On failure the graph returns a degraded `MIXED` regime with confidence 0.0 plus `guardrail_violations` in state, instead of raising.
6. **Decision engine** — `DecisionEngineInterface` in `schemas/analyst_reports.py` with a deterministic `RulesDecisionEngine`; outputs are bounded enums (`MarketRegime`, `RiskCategory`, `AnalystStance`, `AdjustmentGateDecision`), not free text.

### Schema gotchas

- `AnalystReport` validators enforce stance/confidence consistency (STRONG_* needs ≥0.7, BULLISH/BEARISH ≥0.5), length limits on key_points (200) / evidence (300), and reject generic risks like "market risk". Test fixtures must satisfy these.
- A plain-string gap is CRITICAL only if it contains the word "critical"; use a `DataGap`/dict with `severity="critical"` to block the run deliberately.
- `data_gaps` accepts strings, dicts, or `DataGap` objects (with `DataGapSeverity`) for backward compatibility; use `AnalystReport`'s `data_gaps` validator (it already normalizes to `DataGap`) when consuming them.
- Analyst/decision enums, `DataGap`, `AnalystReport` and `DecisionResult` are defined once in `schemas/analyst_reports.py`; `schemas/graph_state.py` re-exports them.
- `GraphState.decision` / `adjustment_gate_decision` are `DecisionResult` models inside nodes (use attributes, not `.get`), but nodes must return them as dicts (`model_dump(mode="json")`).
- Persistence: `database/database.py` SQLite wrapper + Alembic; settings via Pydantic Settings reading `.env` (see `.env.example`).
- Snapshot tables (migration `002`) reject UPDATE/DELETE via triggers; correct a forecast with `ForecastSnapshotStore.record_correction` (new version, original `made_at` kept). Each load re-checks a hash of the stored values. Evaluation must score originals (`list_for_ticker` returns version 1 by default).
- The report writer is deterministic and refuses numbers not traceable to the snapshot (`find_unsupported_numbers`). Bump `versions.py` `PREDICTOR_PROMPT_VERSION` when `build_predictor_prompt` changes; analyst prompt files and response schemas are versioned by content hash automatically.

## Design rules (from Plan.md / README)

- Numbers (indicators, probabilities, prices) come from Python code, never from the LLM; LLMs only interpret supplied structured facts.
- Every LLM call returns a Pydantic structured output — no regex parsing of free text.
- Keep LangGraph state compact: no DataFrames or article bodies in state; store in SQLite/cache and pass summaries/keys.
- Forecast snapshots are immutable once stored; evaluation must be point-in-time (no lookahead).
- LLM-adjusted forecasts are always compared against the quant baseline; calibration changes must be bounded and auditable.
- Use structlog (`stock_analysis.logging`), not `print` (ruff `T20` enforces this); no bare `except`; type hints and docstrings on public functions.
